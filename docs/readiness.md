Mode: `maintain` for the exact-pane CSS cutover, separate OMP/pi launch commands, persisted per-pane read state, opt-out sweeps and repeatable native verification. Scope: source-only Tern plugin at https://github.com/yoyooyooo/tern-tab-status. These samples do not establish universal compatibility or repair Tern's timer-budget mechanism. The [current cutover evidence](#current-css-cutover-evidence) is separate from historical publication and native runs below.

The two READMEs remain equivalent and cross-linked. The canonical repository, package and plugin ID is `tern-tab-status`; its display name is Tern Tab Status. Runtime distribution is `plugin.toml`, `host.luau`, `window.luau` and `LICENSE`; `status.luau` has been removed. Host enumeration preserves full native pane IDs as decimal strings. Window lookup identifies direct omp/pi executables or bounded shell-hosted `omp.session`, then emits CSS for exact native `.tn-dk-c[data-pane][data-st]` elements. Native states drive status without production `agents:list()` or status writes to `tab.color`. Focus/completion events maintain read markers; manual native colors remain intact. Both launchers retain their original preference-restoration behavior.

The later Pi false-blue fix additionally runs asynchronous local `tern inspect --json` queries while enabled with a recognized Pi pane. Blue now requires the daemon's exact-pane `working=true`, because window busy can retain the long-lived launch shell. One query per window may be in flight, with a 1.5-second timeout; failed or unavailable observations clear Pi blue. It requires `tern` on Tern's PATH and refreshes on events/750 ms polling. Pi waiting/result colors and OMP states remain native CSS paths. The raw pane/session/client response is discarded; no conversation text is requested or persisted. This supersedes earlier blanket claims that every status transition is independent of polling or that runtime requires no CLI.

Native title/icon sweeps are now opt-out: absent `disable_sweep` means false, including upgrades from the earlier unconditional suppression. The command palette exposes only the applicable **Disable Sweep Effects** or **Enable Sweep Effects** action; shared KV persists the preference independently of Pause. Existing event/poll synchronization applies it across windows. Pause removes suppression without resetting the choice, and Resume reapplies it. The wrapper animation reset remains necessary for dot stacking and does not disable the icon's separate `::before` sweep. See [sweep option evidence](#sweep-option-verification-on-2026-10-17).

## Not applicable to this distribution

- npm package publication, exports, registry name reservation, OIDC, release channels, and provenance: the npm manifest is private development tooling. Tern consumes a directory.
- Build outputs and generated runtime files: Luau source is the installed runtime. The npm lock pins the check dependency only.
- Hosted release automation and tag checks: there is no release workflow. Contributor guidance defines immutable tags if release tags are introduced.
- Issue/PR templates, dependency update bots, a governance board, and a separate conduct policy: this small repository uses GitHub Issues, pull requests, and documented contribution expectations without additional automation.
- Production dependency advisories and bundled third-party runtime notices: the plugin has no production packages and redistributes no third-party runtime code. The MIT development runtime remains an npm dependency under its own license.
- npm releases and tagged-release readback: distribution currently uses the default source branch; no release tag, GitHub Release, or npm publication is part of this conversion.

## Known native blockers

These are retained investigations of the previous implementation and host mechanisms. The native color bridge still constrains legacy recovery, and timer/OMP limits remain relevant. Exact-pane CSS now bypasses the status color bridge; the old failed title-marker experiment below is not the current implementation. See [current CSS evidence](#current-css-cutover-evidence).

On 2026-10-16, Tern 0.8.3 (`e2b8656`) investigation confirmed that the official [pane/tab ID encoding](https://docs.stencil.so/tern/reference/api-window.md#pane-and-tab-ids) moves the host tag from bit 56 to bit 44 in SDK IDs. The official [number representation](https://docs.stencil.so/tern/concepts/runtime.md#numbers-and-ids) documents double precision; these values are below the exact-integer boundary of 2^53, so the observed difference is not floating-point rounding. The daily Gmail tab's native ID `186951336460326` and SDK ID `11029476016166` differ by exactly `10 * 2^44`. An earlier reproduction used native `281994667753473` and SDK `519691042817`; its artifacts remain under `/tmp/tern-status-integration.rlbr4Y`. `color_tab` accepted SDK and full numeric/string IDs without changing native color. The same-version [upstream issue #30](https://github.com/stencil-hq/tern-sdk/issues/30), including comments [6145881916](https://github.com/stencil-hq/tern-sdk/issues/30#issuecomment-6145881916) and [6172385517](https://github.com/stencil-hq/tern-sdk/issues/30#issuecomment-6172385517), reports the same 44-bit collision. This corroborates the mechanism, not a maintainer-confirmed fix or fixed revision; the application source is not public.

An `arrange` experiment could set color using exact string positions, but could not safely clear it and could reorder tabs. The corrected 2026-10-16 probe at `/tmp/tern-status-repair.hgZoTf/arrange-quoted` passed one JSON-quoted Lua argument, set blue while preserving order/focus, and found that omitting color preserved blue. Null, empty, `none` and `default` did not provide a working clear. The earlier `/arrange/lua-blue.json` lost string quotes and was invalid set/clear evidence. The corrected probe exited. That workaround was rejected; at that time the tab-color runtime could not promise large-ID status or restoration. Current CSS avoids that status bridge, while legacy restoration remains limited. No guessed ID mask or daemon restart is recommended.

The 2026-10-16 experiment at `/tmp/tern-repair-probe.5NP5cI` used `chrome.tab_title` suffixes (`U+2063` plus `U+FE00`–`U+FE03`) and `.tt[title*=suffix] .tn-tc` CSS. Horizontal status worked but the vertical sidebar ignored the formatter; this candidate was rejected and did not change production at that time. Positional CSS was rejected because filtering/reordering/duplicate titles are ambiguous. Opaque snapshot userdata was not an editable color representation. The current full-pane `data-pane`/`data-st` CSS uses neither title markers nor positions and has separate evidence above.

With OMP 18.11.0, the standalone `/verify-confirm` extension command opens a real `ctx.ui.confirm` dialog while Tern's direct agent snapshot remains `idle`. The intermediate native runner therefore failed its yellow/wait assertion. A real dialog without native `waiting_input` is not a passed input-wait scenario. The retained evidence is `/tmp/tern-status-native-integrated-20261015-c/summary.json`, with native snapshots and screenshots in the same directory. Historical pi confirmation results above remain separate from this OMP limitation.

The daily window retained a green dot while the native agent snapshot reported working. Its log recorded `timer exceeded 50 ms`; reload changed that tab to blue despite the plugin listing already saying ready. Isolated 2026-10-16 experiments establish that an over-budget timer callback disables all timer callbacks in the same plugin VM until reload, while commands in that plugin and timers in another plugin continue. The limit measures wall-clock time: an 80 ms busy callback triggered it, and a synchronous FIFO read with a 185 ms `SIGSTOP` while blocked exceeded the budget after resume. The same read without `SIGSTOP` completed in 15.740 ms and the second timer continued. Native waiting and descheduling can therefore consume the budget; CPU work alone does not explain it. Those isolated experiments do not identify the daily failing phase; the actual-callback capture below narrows it. Reload remains temporary recovery.
