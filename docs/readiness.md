# Source distribution readiness

Mode: `maintain` for separate OMP/pi launch commands, direct agent snapshot polling, and repeatable native verification. Scope: the source-only Tern plugin repository at https://github.com/yoyooyooo/tern-tab-status. Version `0.2.0` is an unreleased update. Earlier publication and hosted checks below apply to their named revisions. Final native verification completed with ten passing scenarios and one required unsupported OMP confirmation scenario, so its overall result remains failed. Known Tern 0.8.3 blockers prevent an unconditional compatibility claim.

The English README addresses external Tern users; the Chinese version serves the original user community. Both are maintained and cross-linked. The canonical repository, package, and plugin ID is `tern-tab-status`; its display name is Tern Tab Status. Runtime entry points remain unchanged. OMP and pi Agent Blocks share status rules, with separate commands that open empty conversations in new tabs and restore the configured default Agent command and placement after creation. Polling reads direct `cx.agents:list()` metadata, with a bounded `omp.session` descriptor fallback for shell-hosted OMP identification. Native attention governs completion/failure colors; the plugin never acknowledges that attention.

## Not applicable to this distribution

- npm package publication, exports, registry name reservation, OIDC, release channels, and provenance: the npm manifest is private development tooling. Tern consumes a directory.
- Build outputs and generated runtime files: Luau source is the installed runtime. The npm lock pins the check dependency only.
- Hosted release automation and tag checks: there is no release workflow. Contributor guidance defines immutable tags if release tags are introduced.
- Issue/PR templates, dependency update bots, a governance board, and a separate conduct policy: this small repository uses GitHub Issues, pull requests, and documented contribution expectations without additional automation.
- Production dependency advisories and bundled third-party runtime notices: the plugin has no production packages and redistributes no third-party runtime code. The MIT development runtime remains an npm dependency under its own license.
- npm releases and tagged-release readback: distribution currently uses the default source branch; no release tag, GitHub Release, or npm publication is part of this conversion.

The configured default remained `omp`, and the isolated settings file remained `{}` after launch. That initial implementation created a split and moved it into a new tab; the daily-window failure and replacement are recorded below.

A separate test-only spawn filter attached an offline synthetic provider to pi 1.1.0 while retaining the production launch command. Real Pi request handling produced a blue tab while working, a green tab after completion, and a red tab after a provider error. Focusing the failed pane cleared native attention and restored its original uncolored state. A real `ctx.ui.confirm` produced `waiting_input` and a yellow tab. Native screenshots were inspected for the green and yellow dots; these are local verification captures, not replacements for the published README illustration. No external model was used for this Pi smoke run. The OMP launcher opened the native OMP 18.11.0 surface; this update did not repeat an OMP model request.

Ordinary-shell pi remains outside Tern's agent list, and wrapper executable names are not detected automatically. The two launch commands preserve the default command and placement after returning; they temporarily write both preferences during synchronous creation. Earlier hosted CI, URL-install, and GitHub-rendering evidence applies only to its recorded source revisions.

## Known native blockers

Tern 0.8.3 has an observed gap between native and SDK tab IDs in an existing daemon. Native tab `281994667753473` appeared as SDK ID `519691042817`. `color_tab` accepted the SDK ID and the full ID as numbers or strings without raising, but native color did not change. Lost ID bits are a suspected cause, not a confirmed upstream diagnosis. Local reproduction artifacts are retained under `/tmp/tern-status-integration.rlbr4Y`, including `native-inspect.json`, `daily-color.json`, `daily-full.json`, `daily-string.json`, and `daily-numeric.json`. These are local troubleshooting evidence, not public conversation transcripts.

An `arrange` experiment could set color using exact string positions, but could not safely clear it and could reorder tabs. That workaround is rejected. The plugin cannot promise status colors or Pause restoration for these large-ID daily-session tabs. Fresh low-ID daemon success does not resolve the existing-daemon limitation. No guessed ID masks or daemon restart is recommended.

With OMP 18.11.0, the standalone `/verify-confirm` extension command opens a real `ctx.ui.confirm` dialog while Tern's direct agent snapshot remains `idle`. The intermediate native runner therefore failed its yellow/wait assertion. A real dialog without native `waiting_input` is not a passed input-wait scenario. The retained evidence is `/tmp/tern-status-native-integrated-20261015-c/summary.json`, with native snapshots and screenshots in the same directory. Historical pi confirmation results above remain separate from this OMP limitation.

```sh
node scripts/verify-native.mjs --doctor
node scripts/verify-native.mjs --case launch
node scripts/verify-native.mjs
```

It retains `summary.json`, source hashes, versions, snapshots, screenshots, runtime logs, and owned-process cleanup receipts at its printed output directory. Use `--out <new-directory>` to choose that directory. Failed and unsupported scenarios stay failed/nonzero, even if later cases pass.
